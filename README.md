# 月明·抖音封面批量更新

`moonlit-douyin-cover-updater` 将已有封面批量替换到抖音已有视频，支持错图、黑边、比例错误和漏替换修复。逐条处理3:4与4:3，跳过私密视频，记录进度，提交后重开编辑器并查看公开主页的实际图片。

这是供浏览器Agent执行的 Skill；**不是独立运行的无人值守上传程序**。同一账号的写入串行执行，失败后先看平台是否已经保存，再续跑。

## 安装

克隆到你的Agent技能发现目录；Codex默认目录示例（目标目录须不存在）：

```bash
git clone https://github.com/zzyong24/moonlit-douyin-cover-updater.git ~/.codex/skills/moonlit-douyin-cover-updater
```

如果已安装，先保留本地修改再更新仓库。其他支持Agent Skills的宿主可把仓库根目录安装为 `moonlit-douyin-cover-updater`。安装后启动新会话以加载技能。

## 使用

可以直接说：

- “用月明·抖音封面批量更新，把这批旧封面换成对应作品的新封面，私密作品跳过。”
- “这些作品有黑边或没换完，只修复这一批，横版竖版都核对。”
- “继续上一批封面更新，先检查已提交的，不要重复上传。”

Agent会寻找当前作品库中的双比例文件，建立 [批次队列](templates/batch.json)，核对账号与真实作品ID，再逐条上传。上传授权必须来自当次任务，批次里的历史授权记录不产生下一轮授权。

## 需要什么

- 能读取截图、定位页面、上传本地文件的宿主浏览器工具，或已安装并配置的 `ego-browser`；以该工具自己的安装文档为准。
- 已在该浏览器登录正确抖音账号。技能不导出或保存登录态。
- 每条作品已确认的3:4和4:3封面：推荐1080×1440、1440×1080；其他精确同比例文件可以使用。
- 可写的调用方作品库或运行目录，用于队列、回执和截图。

已有文件的上传流程可单独使用。需要生成/重做封面时使用 [moonlit-video-cover](https://github.com/zzyong24/moonlit-video-cover)。完整新视频发布使用 [moonlit-video-publisher](https://github.com/zzyong24/moonlit-video-publisher)；在Moonlit工程中按实际激活名称解析共享上传契约。

## 完成标准

| 阶段 | 必须观察到的结果 |
| --- | --- |
| 源图 | 双比例尺寸和实际构图正确，没有内嵌异比例图片或非设计黑边 |
| 上传 | 窗口完成初始化，所选正确图片稳定显示 |
| 编辑完成 | 窗口关闭，主页面两个比例都显示正确新图 |
| 提交 | 平台接受修改，返回管理页或给出明确成功提示 |
| 独立重开 | 同一作品两个比例仍保存正确图片 |
| 公开主页 | 同一作品真实封面、标题和裁切都正确 |

**资源ID变化不能证明图正确**，重新上传错图也会产生新ID。只通过提交的条目标 `submitted`；双槽保存与公开图像都确认后才标 `verified`。原作品的发布状态不会因封面操作而改变。

## 进度与恢复

[单作品回执](templates/receipt.json) 保存文件哈希、比例、资源ID、真实观察及证据路径；队列在每条完成后保存。恢复先核验已提交和中断作品，避免重复消耗修改机会。账号不符、验证码、平台拒绝、机会耗尽或用户接管时停止写入并记录原因。

私密视频默认跳过。本技能不修改可见性、不隐藏或删除作品、不改标题文案、不发布新视频，也不处理其他平台。

## 数据与限制

本地文件经平台官方上传界面发送到抖音。队列、截图和回执留在调用方目录；不发送给本仓库或第三方服务器。不保存Cookie、Token、带签名CDN链接或浏览器资料。

技能流程来源于真实批量更新中的纠错：槽位顺序变化、异步初始化、外层像素正确但内容带黑边，以及资源ID变了却仍是旧图。此前实际操作已完成11条目标封面的主页图像核对；本包是对流程的整理，未用新安装包重新提交一轮真实作品，未做独立执行者验收。不同系统、浏览器适配器与未来平台页面需要现场检查，不能保证所有宿主即装即用。
