# 文件、队列与回执

## 准备

运行目录由用户工作区或宿主提供，例如调用方的 `maintenance/runs/<run-id>/`。不要把用户批次写到技能目录。批次、回执和截图中的路径相对运行目录或明确的作品根目录；用户输入的相对文件路径必须先按其所属根目录解析，不能按当前shell目录猜测。

每条作品保存：真实平台作品ID（字符串）、完整标题、所属账号、作品根目录、两张源图的路径、尺寸和SHA-256。运行时另留本次用户授权来源和时间，仅作为历史证据。用户要求全量时，从本人公开作品列表获取目标，不从SEO页脚、推荐视频或他人列表采集。置顶、滚动分页和虚拟列表不得造成漏项或重复；以ID去重。

源图先确认文件存在、能解码、实际宽高分别符合3:4与4:3且分辨率足够；文件名不能作为尺寸证据。用宿主图像工具检查每张主题及画面边界，不以像素比替代视觉判断。源图改变后重算哈希并使旧验收失效，保留旧回执，不原地改历史。

## 状态

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| pending | 清单已建立，未查看现场 | 核对账号、作品及源图 |
| inspected | 现场与映射已确认 | 上传，或直接核验已经正确的封面 |
| uploading | 本作品窗口正在编辑 | 恢复时先看当前UI及保存状态 |
| submitted | 提交已被页面接受，尚未完整核验 | 独立重开双槽并刷新主页 |
| verified | 双槽保存和主页实际图片均匹配 | 保存回执，跳过重复提交 |
| skipped_private | 页面确认私密，按默认范围跳过 | 不上传、不改可见性 |
| skipped_not_video | 确认不是本轮视频目标 | 不上传 |
| blocked | 本条有可定位的阻断 | 记录原因和恢复前提 |

`submitted`与`verified`必须区分；资源ID变化不升级状态。已正确且没提交的作品也可 `verified`，回执写 `action: already_correct`、`submitAccepted: false`；不能假造一次上传。

队列是运行进度投影，单作品回执是操作事实。先写单作品回执，再更新队列；用同目录临时文件加原子替换保存，保留尝试历史。中断后若两者冲突，以回执及实际平台状态恢复，不以队列状态再次自动提交。

## 证据

每个比例记录：可见标签、源路径/哈希/尺寸、替换前资源ID、完成后主卡片资源ID、独立重开资源ID、实际图像是否匹配、截图路径和观察时间。

最终竖版另记录：公开主页同ID卡片、实际画面匹配、标题完整、非设计黑边/拉伸检查和截图。不要记录完整带签名CDN链接。编辑器横竖两个接受标识通常应不同；相同则重新检查是否错误复用了一个裁切，不能直接过关。

截图不存在、图像仍在加载、卡片正悬停播放、平台审核中或主页还未变化时，不能写 `verified`。人工观察字段只写实际观察，不用默认true。截图只是证据，不自动形成用户质量认可。

## Moonlit作品库集成

遵循宿主AGENTS和维护CLI。读取 `work.json.artifacts` 选当前文件；新制作先guard/impact并登记版本。已有文件仅做平台上传时，写对应作品分发事件，不重新登记不变的图片或手工双写current。私人作品跳过不是隐藏动作；批次不改变作品核心命题、标题、原发布凭证和公开状态。
