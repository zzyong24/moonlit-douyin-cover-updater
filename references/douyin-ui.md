# 抖音已有作品双封面更新

本流程由能读图的浏览器Agent执行，没有无人值守的盲点脚本。浏览器控制、文件选择和等待仅使用宿主工具已公开的API。页面结构会变化，先读当前页面，以下选择器只是现场见过的定位线索。

## 单一浏览器会话

复用任务已有空间及页面，记录其标识。若需要首次创建，建立一个命名任务空间；所有提交串行执行。多个Agent/窗口不得同时写同一账号。本技能不要求安装新的浏览器扩展或导出登录态。

使用ego-browser时先读已安装的ego-browser技能/CLI文档。典型调用是 `ego-browser nodejs` 中通过 `taskSpace(<已有空间ID>)`、`task.page(<已有页ID>)` 获取页面，再调用文档支持的 `snapshot`、`screenshot`、`click`、`setInputFiles`、`waitForFunction`。不要把示例空间ID当账号配置。宿主提供其他浏览器工具时使用其官方文件上传接口，不能用脚本改DOM来伪造封面。

## 定位作品

从账号本人作品管理页选择目标，获取真实编辑链接/作品ID。核对登录账号、地址中的ID、完整标题及公开状态；列表截断标题不够。现场曾使用 `creator.douyin.com/creator-micro/content/post/video?mid=<作品ID>&enter_from=edit_item`，但直接进入只适用于已从本人列表确认的ID，不能凭猜测访问。

标题已加载不等于图片已加载。等待两个封面主卡片的图像出现、控件可用后再读现场；导航超时只说明等待结束，检查当前状态后恢复，不立即重复导航或提交。记录剩余修改机会，以页面提示为准，不硬编码永久限制。

## 双槽操作

1. 读取每个封面主卡片旁的可见标签，动态形成标签→卡片映射。现场曾有 `.cover-ybR0xM`，父节点含标签；该class可能变化。横、竖顺序会随作品变化。
2. 进入一个比例的真实编辑窗口，核对窗口标题及预览标签。等待当前旧图/控件初始化完成、加载遮罩消失，再使用该窗口的文件输入。现场曾有 `.upload-BvM5FF input.semi-upload-hidden-input`；不要匹配背景页面的上传输入。
3. 选入映射文件，观察画布及对应比例预览。等待具体正确图片稳定出现；不能仅固定sleep后宣布上传完成。若仍旧图，先等待窗口稳定再重新选择，不先点完成。核对主题文字、人物姿势与证据图，避免同风格不同作品错传。
4. 检查目标画幅自然铺满、标题安全区、人物比例。对应窗口的灰色工作台边缘不是封面黑边；以画布内边界和手机预览判断。
5. 点本窗口“完成”，等待窗口真正关闭。主卡片完成异步更新后再比对实际图片与资源ID，不能在关闭瞬间读取旧卡片。
6. 对另一比例重复。确认主页面两个图分别为真实3:4/4:3设计，资源ID不同。每完成一个比例留截图/观察字段。
7. 两图都通过后仅点一次“提交修改”，等待平台接受、返回作品管理或明确成功提示。意外提示先读内容，不随意同意新条款或更改其他字段。

固定DOM序号、输入文件成功、canvas正确、弹窗关闭、资源ID变化，都不能各自代替最终保存证据。

## 独立重开及公开核验

提交后离开当前编辑器再打开同一作品，重新识别两种标签，等待图片真实加载并截图，对照源图。公开主页重新导航/完整刷新，等待目标列表真实加载，按作品ID定位；不要用页面任意首个视频链接认定目标。

将鼠标移到卡片之外后截图，避免悬停触发视频播放覆盖封面。滚动逐行检查；虚拟列表按ID累计记录。对每条验收实际主题图、完整主标题、自然比例、无非设计黑边/拉伸。主页缩略图可能是323×430一类平台缩放，不能拿它的小像素尺寸否定源图3:4；真正的黑边与内容裁切仍须肉眼检查。横版验收来自独立重开的4:3槽位，不能从竖版主页推断。

若主页仍旧图或正在审核，保留 `submitted`，在可用的等待/刷新后再查看；未完成时明确列出该条。不得把改ID的旧图、视频首帧或另一作品的新图算成目标封面。
